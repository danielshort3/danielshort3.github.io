The wordmarks and banners use outlined Inter lettering so they render consistently without installed fonts. Their SVG title/description preserves readable text descriptions. PNG wordmarks and the white mark retain transparency; social images have a white background. No logo shadows, gradients, or distortion are applied in this export kit.

## Authoritative sources and regeneration

- Drawing: `img/brand/00-ds-logo-master-full-color.svg`.
- Name and domain: `content/site/settings.json`.
- Personal tagline: `content/audiences/personal.json`.
- Brand and category colors: `css/variables.css`.
- Typography: `build/fonts/Inter-Latin.ttf`, the TrueType copy of the website's bundled Inter font.
- Layout and outlined type: `build/generate-brand-assets.py`.

Run the optional authoring command from the repository root:

```powershell
python build/generate-brand-assets.py
```

It requires FontTools and the repository's existing Node.js/Sharp installation. No browser font loading, font download, or new application dependency is required. A local `tmp/pdfs/brand-guide-deps` FontTools installation is recognized when present. Pass `--output-dir <folder>` for a review export, `--svg-only` to skip rasterization, or `--node <executable>` when Node is not on the path.

This command regenerates the six SVG/PNG pairs listed above, excluding the master, existing reversed/monochrome variants, and favicon. It is separate from `npm run build`; the website build copies the reviewed assets into `public/`. Regenerate favicons with `node build/resize_logo.js`. Refresh metadata through its authoritative site settings and generator, not generated HTML.

Before sharing, inspect the actual-sized wordmarks on the intended background, all-white transparency, the entire social card at thumbnail size, and LinkedIn's crop. Website build and metadata checks do not upload banners to external social accounts or rebuild the Android app.

## Retained older assets

The remaining numbered templates and hero artwork are retained for compatibility and reference. They are not automatically the current personal wordmark or social-share design. In particular, `07-website-hero-light-version.png` and the `23`–`27` hero images remain referenced as CSS backgrounds on audience pages. Do not replace those backgrounds with a social card or remove them based only on the default social metadata changing.

Tool and game share cards in `img/social/` are separate generated outputs: their source is `build/lib/social-previews.js`, rendered by `build/generate-social-previews.js` during the website build. Portfolio preview captures are owned by their project content and image pipeline. Neither family is regenerated by the secondary-brand authoring command.

See `docs/visual-style.md` and `documents/brand_guide.pdf` for the broader visual system, and `docs/REPOSITORY_MAP.md` for source ownership.
