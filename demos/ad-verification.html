    How this simulation works

    Parallel people, sequential records. All five active travelers stay visible. Their ad, website, and destination events overlap. Events wait for a single block writer; a traveler’s recorded check appears in the same frame as its block. A finished traveler fades out and a new one takes that lane, without resetting anyone else.

    Optional outcomes. A website visit is not required for a destination visit. An unobserved visit does not produce a visit block. “Measurement ended” records the observations within the simulated window—not proof that an unobserved trip never happened. The selected mix applies to new arrivals, not travelers already being measured.

    Real cryptography, fictional observations. Blocks use SHA-256, ECDSA signatures and the previous block’s fingerprint. Click any block to inspect it, edit a copy, and test verification. All identities and validators run locally in this browser: this is not independent network consensus. Blockchain checks the record, not whether a human saw an advertisement or visited a destination.

    No real people, device IDs, GPS, or advertising services are connected. Timing and outcomes are illustrative, not measured conversion rates. Reloading or resetting discards this browser session. The 256-block limit stops new arrivals early enough for existing travelers to finish.
