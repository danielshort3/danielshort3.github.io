    What this demo proves—and what it does not

    Real record verification. Each block is created as its event plays, using SHA-256 hashes, ECDSA signatures, the previous block’s hash, and three local validator approvals. Both animations use one clock and one commit. One event per block is a teaching simplification; blocks can contain many events.

    Simulated people and outcomes. The scenario supplies fictional website and destination events. A destination visit is an attribution provider’s claim, not something blockchain independently observes. No device IDs, GPS coordinates, location access, or live advertising connections are used. Example time is compressed; it is not a real travel timeline.

    No observation is not proof of no visit. A skipped website or destination visit does not create a visit block. A final signed summary records only what was observed within the example window.

    A local miniature blockchain. All signing keys and validators live in this browser, not independent organizations. The chain checks records against the session’s original keys and checkpoint, not the truth of the claims. Reloading or resetting discards the chain. Continuous play stops before 256 blocks to keep the demo responsive.
